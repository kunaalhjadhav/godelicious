# Godelicious Customer App — Standalone Build Guide

This turns `customer-app/` into a real, independent, installable Android app — not something
merged into another project. The JS/UI code is 100% complete already (screens, navigation,
cart, auth, API client, all wired to your backend). What's missing is the **native Android
project scaffold** (the `android/` folder — Gradle files, `MainActivity`, app icons, etc.),
which has to be generated by the React Native CLI on your machine, because it downloads
platform-specific binaries and templates that require network access and your local Android
SDK — I can't produce that from a text-based environment.

Once scaffolded, dropping in the code you already have takes minutes, and building the APK is
one command.

---

## Step 1 — Scaffold a fresh, standalone RN project

Pick a folder **outside** the `godelicious/` project you downloaded, then run:

```bash
npx react-native@0.75.4 init GodeliciousApp --version 0.75.4
```

This creates a brand-new, complete, standalone `GodeliciousApp/` folder with a working
`android/` and `ios/` folder, correctly matched Gradle/AGP/Kotlin versions for RN 0.75.4 (the
version this project's `package.json` targets), a debug keystore, app icons, everything. This
is the same tool that made the project you were already debugging earlier — running it fresh
avoids re-inheriting any half-configured state.

Confirm it runs before changing anything:
```bash
cd GodeliciousApp
npx react-native run-android
```
You should see the default "Welcome to React Native" screen on your emulator/device. If this
works, your native toolchain (JDK, Android SDK, Gradle) is confirmed healthy — the exact issues
you fixed earlier in this conversation.

---

## Step 2 — Drop in the Godelicious app code

From the `godelicious-project.zip` you downloaded, copy these **into** the new `GodeliciousApp/`
folder, **overwriting** the placeholder files it came with:

```
customer-app/App.js            → GodeliciousApp/App.js
customer-app/app.json          → GodeliciousApp/app.json
customer-app/index.js          → GodeliciousApp/index.js
customer-app/src/               → GodeliciousApp/src/
```

Do **not** overwrite `android/`, `ios/`, `package.json`, `babel.config.js`, or
`metro.config.js` from `customer-app/` — the ones the CLI just generated in Step 1 are correctly
matched to your installed toolchain. (The versions in `customer-app/` are reference copies in
case you ever need to compare or rebuild from scratch.)

---

## Step 3 — Install the app's dependencies

```bash
cd GodeliciousApp
npm install @react-native-async-storage/async-storage @react-navigation/native @react-navigation/native-stack @react-navigation/bottom-tabs react-native-safe-area-context react-native-screens @react-native-community/datetimepicker @react-native-community/geolocation react-native-webview react-native-razorpay
```

Android autolinks these automatically with RN 0.75+ — no manual native edits needed for most of
them. **Two exceptions:**

### Step 3a — Add location permission (Android)

Open `android/app/src/main/AndroidManifest.xml` in the freshly-scaffolded project and add, just
inside the `<manifest>` tag (before `<application>`):
```xml
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
```
Without this, tapping "use my current location" at checkout will fail on Android with a
permission error. iOS needs a similar entry in `Info.plist` (`NSLocationWhenInUseUsageDescription`)
if you build for iOS later.

### Step 3b — Razorpay native setup (Android)

`react-native-razorpay` autolinks, but Razorpay's own native SDK needs one addition to
`android/app/build.gradle` — inside the `dependencies { ... }` block, add:
```groovy
implementation 'com.razorpay:checkout:1.6.33'
```
(check [Razorpay's Android SDK docs](https://razorpay.com/docs/payments/payment-gateway/android-integration/standard/) for the current recommended version if this one has been superseded by
the time you build). Without this, the app will crash immediately when `RazorpayCheckout.open()`
is called, with a `ClassNotFoundException` for Razorpay's checkout activity.

## Step 4 — Point the app at your backend

Open `src/api/client.js` and set `API_URL`:

| Target | URL |
|---|---|
| Android emulator | `http://10.0.2.2:5000` (default — already set) |
| Physical Android device | `http://<your-computer-LAN-IP>:5000`, e.g. `http://192.168.1.5:5000` |

Phone and computer must be on the same Wi-Fi for the physical-device case. Your backend also
needs to actually be running (`cd backend && npm run dev`) and reachable from wherever the app
runs — for a physical device or production build, that means it needs to be deployed somewhere
public (Railway, Render, a VPS), not just `localhost`. See `SETUP_GUIDE.md`'s production notes.

**For a genuinely production build**, don't point at `localhost`/`10.0.2.2` at all — deploy the
backend first, then set `API_URL` to that public URL before building the release APK. An APK
pointed at your dev machine's IP will stop working the moment you close your laptop.

## Step 5 — Test it end-to-end (debug build)

```bash
npx react-native run-android
```

Log in with the seed customer account, browse the menu, place an order, confirm it appears in
the admin dashboard. Fix anything before moving to a release build — debugging is much easier
here than after signing.

---

## Step 6 — Generate a release keystore (one-time, production only)

A release APK must be cryptographically signed. Generate a keystore (keep this file and its
passwords safe forever — losing it means you can never update the app under the same identity
again):

```bash
cd android/app
keytool -genkeypair -v -storetype PKCS12 -keystore godelicious-release.keystore -alias godelicious -keyalg RSA -keysize 2048 -validity 10000
```

You'll be prompted for a keystore password, key password, and identity details — remember the
passwords.

---

## Step 7 — Configure signing

Add to `android/gradle.properties` (create the file if it's not there, or append):
```properties
GODELICIOUS_UPLOAD_STORE_FILE=godelicious-release.keystore
GODELICIOUS_UPLOAD_KEY_ALIAS=godelicious
GODELICIOUS_UPLOAD_STORE_PASSWORD=<your keystore password>
GODELICIOUS_UPLOAD_KEY_PASSWORD=<your key password>
```

In `android/app/build.gradle`, inside the `android { ... }` block, add a `signingConfigs`
block and point the release build type at it:

```groovy
android {
    ...
    signingConfigs {
        release {
            storeFile file(GODELICIOUS_UPLOAD_STORE_FILE)
            storePassword GODELICIOUS_UPLOAD_STORE_PASSWORD
            keyAlias GODELICIOUS_UPLOAD_KEY_ALIAS
            keyPassword GODELICIOUS_UPLOAD_KEY_PASSWORD
        }
    }
    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled true
            proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
        }
    }
}
```

(**Never commit `gradle.properties` with real passwords, or the keystore file, to a public
repo** — the `.gitignore` in `customer-app/` already excludes `*.keystore`.)

---

## Step 8 — Build the release APK

```bash
cd android
gradlew.bat assembleRelease
```

On success, your installable APK is at:
```
android\app\build\outputs\apk\release\app-release.apk
```

Copy this file to your phone (or upload it somewhere) and install it directly — this is a real,
signed, standalone APK you can distribute for testing (sideloading) right now.

---

## Step 9 — Going further (Play Store)

The Play Store requires an **AAB** (Android App Bundle), not a raw APK:
```bash
gradlew.bat bundleRelease
```
Output: `android\app\build\outputs\bundle\release\app-release.aab`. Upload that to the Play
Console. You'll also need: a Play Console developer account ($25 one-time), a privacy policy
URL, app screenshots, and a content rating questionnaire — all Play Store account requirements
independent of the code itself.
